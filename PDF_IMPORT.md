# PDF statement import

Open **Statement Check > Import PDF Statement > Choose PDF**. Select the numeric date order before scanning (day/month/year by default). Numeric year-first dates normally use year/month/day; choose **Year / Day / Month** explicitly for that layout. For example, `2026/07/10` can mean July 10 or October 7. Changing the order after extraction requires a rescan so already-normalized dates are never silently reinterpreted. Existing checking profiles, interest/tax rules and case-sensitive text checks still apply.

The browser reads each page with PDF.js. Scanned pages are detected from large page images and get fresh OCR even when their hidden text layer looks readable. Digital PDFs retain their text unless missing rows, invalid values or review warnings require OCR. Tesseract reads scans at up to 300 DPI, then reads each table column separately, preserving line positions. Conflicting cells can receive a single-line scan (up to 40 per page). Page images are reused during these passes. A contrast pass locates shaded headings only; transaction values come from the original image. When separate readings agree on a date or description, the importer can select that reading and flags the change. Readable amounts and cheque numbers are never replaced by voting: repeated OCR passes can share the same digit error, so conflicting numeric readings require review. Unresolved disagreements retain the primary reading and offer alternatives for review. Amounts and descriptions are never changed merely to fit a balance or configured rule. **Force OCR** ignores embedded PDF text. OCR can retry sideways or upside-down scans. The bundled OCR language is English; Nepali-script tables and handwriting are not supported.

Dates accept slash, dash and dot numeric separators, two- or four-digit trailing years, and exact English month names/abbreviations (Jan through Dec, including Sept). Jan is January; Jun is June. A small explicit set of OCR month confusions such as `0ct`, `0tc`, `Otc` and `Se9` is recognized in the date column and flagged for verification. Unknown month words, impossible dates and unreadable numeric dates remain errors. Dates display and export as `YYYY-MM-DD`.

The importer locates Date, Description/Particulars, Debit, Credit and Balance headings; Cheque No. is optional. It merges pages in document order, drops repeated headers and removes explicit matching carried-forward/brought-forward balances at page boundaries. Ordinary repeated transactions are retained. Letterheads, page numbers, totals and signature/stamp areas outside the table are excluded. A stamp overlapping transaction text may need manual correction.

Review the extracted table before using **Import and check statement**. Unreadable amounts are retained for correction instead of becoming zero. Low-confidence OCR and pages with no detected rows show review messages. Edit cells, insert missed rows or remove a non-transaction row. The original PDF remains available in another tab for comparison. **Download extracted Excel** creates an `.xlsx` file with text descriptions and cheque numbers preserved, including leading zeroes. Import uses that same workbook through the existing Excel endpoint, with the same saved history, row editor and validation errors.

Highlighted review cells include running-balance disagreements, dates out of order, amounts on both sides, case-sensitive deposit/withdrawal label mismatches and wrong-side descriptions. Names may differ. **Review current cells** refreshes these checks with the current text settings. The existing statement checker remains responsible for the complete interest, tax, holiday, cheque and optional extra-text rules after import. Corrections and alternative readings are editable; review warnings do not prevent importing a syntactically readable statement for those checks.

PDF/OCR processing happens in the browser; no PDF or image is sent to a third-party OCR service. Only the extracted workbook is uploaded to the app when importing. Scan state and the original PDF link are cleared on logout. Named statement profiles are unchanged.

Limits: 25 MB per PDF, 50 pages, 5,000 extracted rows, 16 megapixels per rendered page and 120 seconds per OCR recognition pass. Password-protected documents must be unlocked first. Use a recent desktop browser with WebAssembly and JavaScript modules. Review remains necessary: no OCR engine can guarantee perfect extraction from poor-quality scans.

## Hosting

Upload the complete `static/vendor/pdf-ocr/` directory together with the application assets. It contains pinned PDF.js 6.4.299, Tesseract.js 7.0.0, its WebAssembly core and English language data, and fflate 0.8.2. Licenses and SHA-256 hashes are in `PROVENANCE.md`. Files load only from the same origin; there is no CDN requirement or Python/Tesseract installation requirement on PHP hosting. The bundle is about 33 MB and is loaded when PDF import/OCR is used.

The supplied content security policy allows same-origin workers and WebAssembly (`wasm-unsafe-eval`), without enabling JavaScript `unsafe-eval` or third-party origins. PHP Apache hosting gets `.mjs` and `.wasm` MIME types from `.htaccess`. Python serves these types explicitly. For Nginx or other frontends, serve `.mjs` as `text/javascript` and `.wasm` as `application/wasm`; ensure any reverse-proxy CSP permits the same worker/WASM capability. Keep the English `.traineddata.gz` file available as a binary gzip file, not an automatically decompressed HTTP response.

Library documentation: [PDF.js](https://mozilla.github.io/pdf.js/) and [Tesseract local installation](https://github.com/naptha/tesseract.js/blob/master/docs/local-installation.md).
