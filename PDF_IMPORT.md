# PDF statement import

Open **Statement Check > Import PDF Statement**, choose a recognition mode, then **Choose PDF**. Select the numeric date order before scanning (day/month/year by default). Numeric year-first dates normally use year/month/day; choose **Year / Day / Month** explicitly for that layout. For example, `2026/07/10` can mean July 10 or October 7. Changing the order after extraction requires a rescan so already-normalized dates are never silently reinterpreted. Existing checking profiles, interest/tax rules and case-sensitive text checks still apply.

Two local modes are available:

- **Standard OCR** uses the existing compact English model, page/column recognition and targeted cell retries.
- **Detailed local recognition** (default) uses the full floating-point English `tessdata_best` model. It identifies the statement headings, reads each column, then reads up to 300 populated cells per page individually. Crops follow column boundaries and the gaps between rows, including wrapped descriptions. Larger pages retain column readings beyond that limit and show a review warning. This mode takes longer and downloads an additional 12.8 MB model from your own server on first use. It is not Adobe Acrobat and does not promise identical results.

**Convert to Excel and automatically open in Statement Check** is enabled by default. Configure the profile/texts, interest rate and tax rate before choosing the PDF. After conversion, the workbook goes through the existing Excel importer and displays the original extracted values and checker errors in the statement preview. Unreadable dates or amounts stop automatic import for cell review; they are never converted to zero. Uncheck this option to review/download the extracted Excel first. **Force OCR** remains optional for an unreliable hidden text layer.

**Correct statement**, beside the statement preview, first runs the checker against the selected saved profile or current details. It proposes description label/case corrections for individual selection, preserving names and extra text. Applying a proposal changes an edit draft only. Dates, amounts, balances and cheque numbers are not guessed from a profile. Use **Edit other statement fields** or **Review PDF cells and original** for manual fixes, **Update & Recalculate** to save with the existing interest/tax rules, and **Check Statement** to check again. **Cancel Edit** discards an unsaved correction draft. Profiles and templates are not overwritten.

The browser reads each page with PDF.js. Scanned pages are detected from large page images and get fresh OCR even when their hidden text layer looks readable. Digital PDFs retain their text unless missing rows, invalid values or review warnings require OCR. Tesseract reads scans at up to 300 DPI, then reads each table column separately, preserving line positions. Standard mode retries up to 40 conflicting cells; Detailed mode reads up to 300 populated cells. Page images are reused during these passes. A contrast pass locates shaded headings only; transaction values come from the original image. When separate readings agree on a date or description, the importer can select that reading and flags the change. Readable amounts and cheque numbers are never replaced by voting: repeated OCR passes can share the same digit error, so conflicting numeric readings require review. Unresolved disagreements retain the primary reading and offer alternatives for review. Amounts and descriptions are never changed merely to fit a balance or configured rule. **Force OCR** ignores embedded PDF text. OCR can retry sideways or upside-down scans. The bundled OCR language is English; Nepali-script tables and handwriting are not supported.

Dates accept slash, dash and dot numeric separators, two- or four-digit trailing years, and exact English month names/abbreviations (Jan through Dec, including Sept). Jan is January; Jun is June. A small explicit set of OCR month confusions such as `0ct`, `0tc`, `Otc` and `Se9` is recognized in the date column and flagged for verification. Unknown month words, impossible dates and unreadable numeric dates remain errors. Dates display and export as `YYYY-MM-DD`.

The importer locates Date, Description/Particulars, Debit, Credit and Balance headings; Cheque No. is optional. It merges pages in document order, drops repeated headers and removes explicit matching carried-forward/brought-forward balances at page boundaries. Ordinary repeated transactions are retained. Letterheads, page numbers, totals and signature/stamp areas outside the table are excluded. A stamp overlapping transaction text may need manual correction.

Review the extracted table before using **Import and check statement**. Unreadable amounts are retained for correction instead of becoming zero. Low-confidence OCR and pages with no detected rows show review messages. Edit cells, insert missed rows or remove a non-transaction row. The original PDF remains available in another tab for comparison. **Download extracted Excel** creates an `.xlsx` file with text descriptions and cheque numbers preserved, including leading zeroes. Import uses that same workbook through the existing Excel endpoint, with the same saved history, row editor and validation errors.

Highlighted review cells include running-balance disagreements, dates out of order, amounts on both sides, case-sensitive deposit/withdrawal label mismatches and wrong-side descriptions. Names may differ. **Review current cells** refreshes these checks with the current text settings. The existing statement checker remains responsible for the complete interest, tax, holiday, cheque and optional extra-text rules after import. Corrections and alternative readings are editable; review warnings do not prevent importing a syntactically readable statement for those checks.

PDF/OCR processing happens in the browser; no PDF or image is sent to a third-party OCR service. Only the extracted workbook is uploaded to the app when importing. Scan state and the original PDF link are cleared on logout. Named statement profiles are unchanged.

Limits: 25 MB per PDF, 50 pages, 5,000 extracted rows, 16 megapixels per rendered page and 120 seconds per OCR recognition pass. Password-protected documents must be unlocked first. Use a recent desktop browser with WebAssembly and JavaScript modules. Review remains necessary: no OCR engine can guarantee perfect extraction from poor-quality scans.

## Hosting

Upload the complete `static/vendor/pdf-ocr/` directory together with the application assets. It contains pinned PDF.js 6.4.299, Tesseract.js 7.0.0, its WebAssembly core and English language data, and fflate 0.8.2. Licenses and SHA-256 hashes are in `PROVENANCE.md`. Files load only from the same origin; there is no CDN requirement or Python/Tesseract installation requirement on PHP hosting. The existing bundle is about 33 MB; Detailed mode adds a 12.8 MB compressed model in `best/`. Files load only when needed. Deploy the entire directory, including `best/`.

The supplied content security policy allows same-origin workers and WebAssembly (`wasm-unsafe-eval`), without enabling JavaScript `unsafe-eval` or third-party origins. PHP Apache hosting gets `.mjs` and `.wasm` MIME types from `.htaccess`. Python serves these types explicitly. For Nginx or other frontends, serve `.mjs` as `text/javascript` and `.wasm` as `application/wasm`; ensure any reverse-proxy CSP permits the same worker/WASM capability. Keep the English `.traineddata.gz` file available as a binary gzip file, not an automatically decompressed HTTP response.

Library documentation: [PDF.js](https://mozilla.github.io/pdf.js/) and [Tesseract local installation](https://github.com/naptha/tesseract.js/blob/master/docs/local-installation.md).
